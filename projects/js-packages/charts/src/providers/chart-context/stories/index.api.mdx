# Global Charts Context API Reference

This document provides comprehensive API documentation for the Global Charts Context system.

## GlobalChartsProvider

The main provider component that enables chart context functionality.

**Props:**

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `theme` | `Partial<ChartTheme>` | `defaultTheme` | Custom theme object that gets merged with the default theme |
| `children` | `ReactNode` | - | **Required.** Chart components and other React elements |

## GlobalChartsContextValue

The context value shape provided by `useGlobalChartsContext`:

```typescript
interface GlobalChartsContextValue {
	// Chart registry
	charts: Map<string, ChartRegistration>;
	registerChart: (id: string, data: ChartRegistration) => void;
	unregisterChart: (id: string) => void;
	getChartData: (id: string) => ChartRegistration | undefined;

	// Theme and styling
	theme: CompleteChartTheme;
	getElementStyles: (params: GetElementStylesParams) => ElementStyles;
	resolveThemeColor: (value: string) => string;

	// Series visibility management for interactive legends
	toggleSeriesVisibility: (chartId: string, seriesLabel: string) => void;
	isSeriesVisible: (chartId: string, seriesLabel: string) => boolean;
	getHiddenSeries: (chartId: string) => Set<string>;

	// Color palette resolution state
	isColorPaletteResolved: boolean;
}
```

`isColorPaletteResolved` is `false` until the provider's color cache has been resolved from the DOM and painted. Chart components can use this to defer CSS transitions or animations that would otherwise interpolate from a fallback color to the resolved theme color on initial render.

`resolveThemeColor` resolves a color value — including a `--wpds-*` token or `var(...)` expression — to a hex string in the provider's own (theme-scoped) element. Use it when JS needs the *resolved* value of a themed color, such as reading `theme.backgroundColor` to compute text contrast. It resolves at call time, so the result tracks a light/dark theme switch where the token string is unchanged but its resolved value differs. Returns `''` for an empty input.

## Theming

The package's `--a8c-charts-*` catalog (see `TOKENS.md`) is emitted once at `:root`,
so every chart — whether or not it sits under a `GlobalChartsProvider` — resolves its
colors, focus ring, motion, and border-radius roles from that catalog by CSS
inheritance. Consumers override a role by setting the matching `--a8c-charts-*` custom
property on any ancestor of a chart, including plain CSS with no provider involved —
the closest ancestor wins:

```css
.my-dashboard {
	--a8c-charts-color-grid: #e0e0e0;
}
```

The `theme` prop is a second, narrower override path. Five `ChartTheme` fields
correspond directly to a catalog role, and setting one republishes it as the matching
instance-scoped `--a8c-charts-*` variable on the provider's wrapper element — so the
CSS-painted value (read by SVG/Google Charts through `getComputedStyle`) and the
JS-resolved value (read through `resolveThemeColor` / `getElementStyles`) stay in
step:

| `theme` field | Catalog role |
| --- | --- |
| `backgroundColor` | `--a8c-charts-color-background` |
| `gridStyles.stroke` | `--a8c-charts-color-grid` |
| `xAxisLineStyles.stroke` | `--a8c-charts-color-axis` |
| `xTickLineStyles.stroke` | `--a8c-charts-color-tick` |
| `svgLabelSmall.fill` | `--a8c-charts-color-label` |

A value that already points at the role it would define (the default theme's own
catalog pointer, surviving `mergeThemes`) is not republished — emitting it would make
the custom property reference itself, which CSS discards. Because `theme` is merged
sparsely with `defaultTheme`, a field you don't set falls through to the catalog
default rather than to a separate JS default value.

## ChartRegistration Type

```typescript
interface ChartRegistration {
	legendItems: BaseLegendItem[];
	chartType: ChartType;
	metadata?: Record<string, unknown>;
}
```

## ElementStyles Type

```typescript
type ElementStyles = {
	color: string;
	lineStyles: LineStyles;
	barStyles: BarStyles;
	glyph: <Datum extends object>(props: GlyphProps<Datum>) => ReactNode;
	shapeStyles: CSSProperties & LineStyles;
};
```

`barStyles` carries bar-specific styling resolved from the theme by semantic series type (e.g. `barChart.barStyles.comparison`) — `{ widthFactor?, opacity? }`. It is `{}` for series with no matching bar style and for non-`SeriesData` inputs.
